## 1. The EWMA update rule — STILL TRUE

Source: `firmware/unified_trust_monitor_template/unified_trust_monitor_template.ino`, lines 137
and 194 (identical in both crypto paths):

```cpp
trust_score = (ewma_alpha * current_trust) + ((1.0 - ewma_alpha) * trust_score);
```

Under attack `current_trust = 0.0` (lines 128, 185). The recurrence reduces to
`trust(t+1) = (1 − alpha) · trust(t)`. **Alpha is the weight on the new observation.** Low alpha
= slow decay. Eviction when `trust_score < 30.0` (lines 16, 139, 196). Initial trust 100 (line 17).

Cycles to fall from 100 to below 30: `n(alpha) = ceil(log 0.3 / log(1 − alpha))`

| alpha | cycles | trust sequence (100·(1−α)^k) |
| ----- | ------ | ---------------------------- |
| 0.1   | 12     | 90, 81, 72.9, … 31.38, 28.24 |
| 0.3   | 4      | 70, 49, 34.3, 24.01          |
| 0.5   | 2      | 50, 25                       |

`outline_v2.md` §3.4 still writes `Γ(t+1) = α·Γ(t) + (1−α)·N₀`, the reverse convention. The code
is correct; the document is wrong (unchanged since 2026-08-07).

Firmware structure that matters for every latency figure below: the loop reads serial commands
only between crypto cycles (lines 217-260), then runs one crypto cycle plus `delay(10)` and a
serial print (lines 152, 209). An `ATTACK` therefore takes effect at the *next* cycle boundary.

### 3.4 Physical stop vs logged stop

Script: `audit/physical_stop_crosstab.py`. Motion is commanded from t_attack + 0.5 s to
+ 9.5 s (`stream_wrist_kinematics.py` lines 192-210: Pick@1 s … Pick@10 s, attack thread at
0.5 s). A trial whose joints stay at standstill (max |v| < 0.02 rad/s) through that window
did not execute the trajectory: the safeguard input opened. Across V5 + V6 + V7 (315 trials):

- logged stop but arm kept moving: **0**
- physically stopped but not logged: **8** (V6: 6 in cell 250/0.5, 1 in 500/0.3; V7: 1 in 1000/0.3)

All eight are boundary cells and are explained by §6.5. With the physical column the quantized
prediction `stop iff outage ≥ n(α)·T_cycle` holds in **every** cell of V6 and V7
(ECC: 2×120 = 240 < 250; 4×120 = 480 < 500; 12×120 = 1440 < 2000 and > 1000.
Proxy: 2×232 = 464 < 500 and > 250; 4×232 = 928 < 1000 and > 500; 12×232 = 2784 < 3000 and > 1000).
There is no partial cell.

**Motion at eviction.** In every ECC alpha = 0.5 stop (V5 20/20, V6 34/34), every ECC alpha = 0.3
stop except the 2000 ms cell, and every proxy alpha = 0.5 stop except two, the arm had not
started moving when the input opened (eviction precedes the 0.5-1.0 s motion onset). **A
sub-500 ms stop of a moving arm was never observed.** The physical evidence for those cells is
"the commanded trajectory was never executed". Moving-arm stops exist only in slow conditions
(alpha = 0.1, and V5 stub alpha = 0.3/0.5), velocities at eviction 0.2-0.6 rad/s.

Structure: detection → first decay = partial cycle + one full cycle (ECC 177 ms, 125-228; proxy
309 ms, 258-443); first decay → eviction = exactly one cycle (2.2). Hence

    T_evict ≈ n(alpha) · T_cycle + U(0, T_cycle) + serial

`detection + eviction == total` holds to 0.01 ms in all rows because the three columns are
computed from the same four timestamps (script lines 173-175). It is an identity, not a result.
Detection ≈ one probe timeout because the harness probes at jam onset; it is a lower bound.

### 3.6 Consequence for the safety claim

Only ECC at alpha = 0.5 has a mean under 500 ms (362.8 ms, V6), and its observed maximum is
504.7 ms (V6) / 504.9 ms (V5). With the ZKP-cost proxy nothing is under 500 ms: fastest mean
623.5 ms, fastest single trial 515.4 ms. Inverting the model at alpha = 0.5 with a 500 ms budget
and mean ≈ 2.5·T_cycle gives T_cycle ≲ 200 ms; with the worst case 3·T_cycle, ≲ 167 ms.
